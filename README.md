# 💡 Идеи Batumi Vibe Lab

Пул идей будущих проектов клуба: предлагаем, обсуждаем, собираем команду. Одна идея — один issue. Идея может лежать в бэклоге сколько угодно: в спринт берём то, что созрело, остальное ждёт своего часа.

- [Все открытые идеи](https://github.com/batumi-vibe-lab/ideas/issues)
- [Самые поддержанные](https://github.com/batumi-vibe-lab/ideas/issues?q=is%3Aissue+is%3Aopen+sort%3Areactions-%2B1-desc)
- [Предложить идею](https://github.com/batumi-vibe-lab/ideas/issues/new/choose)

---

## ✍️ Как предложить идею

1. Нажми **New issue** → **💡 Новая идея** и заполни форму. Пиши тезисно, дополнить можно потом.
2. Метки поставятся сами: стадия, цель и рынок из ответов формы и `нужен владелец`, если ты не готов вести проект сам.
3. Предложил идею на встрече или через [форму на сайте](https://vibecoding.ecommercie.com/#projects)? Её перенесёт сюда организатор или контрибьютор и упомянет тебя.

Похожая идея уже есть? Лучше допиши в её комментарии, чем заводи новую.

## 🗣 Как обсуждаем и голосуем

- **Голос — реакция 👍 на описании идеи.** Комментарии «+1» не пиши: они не считаются и засоряют обсуждение.
- **В комментариях** — вопросы, критика, ссылки на конкурентов и ресёрч, «готов участвовать, могу делать X».
- **Итоги обсуждения на встрече** кто-то из присутствующих коротко пишет в комментарий.
- Автор может править описание идеи. Метки меняют контрибьюторы и админы: если метка устарела — напиши в комментарии.

## 🏷 Метки

У идеи четыре независимых признака: стадия, цель, рынок и кто нужен.

### Стадия — одна

Стадия показывает, что с идеей реально сделано.

| Метка                | Когда                                                                      |
| -------------------- | -------------------------------------------------------------------------- |
| `стадия: идея`       | Есть описание. Ставится сама при создании. Это и есть бэклог               |
| `стадия: проверка`   | Кто-то проверяет спрос: ресёрч, интервью, лендинг, реклама на пару сотен $ |
| `стадия: разработка` | Есть репозиторий `proj-*`, пишут код                                       |

Отдельной стадии «отложена» нет: идея, которую никто не трогает, просто остаётся на своей стадии. Давно забытые видно по сортировке **Recently updated** в обратном порядке.

### Цель — одна

| Метка               | Что значит                                               |
| ------------------- | -------------------------------------------------------- |
| `цель: заработать`  | Продукт ради денег                                       |
| `цель: польза`      | Для города, сообщества, open source без расчёта на доход |
| `цель: эксперимент` | Научиться, попробовать технологию                        |

Цель задаёт ожидания команды: с ней до старта понятно, на что идёшь, и проще договориться, кто что получает (правила клуба 2 и 7).

### Рынок — один

| Метка              | Для кого                                |
| ------------------ | --------------------------------------- |
| `рынок: Батуми`    | Экспаты, туристы, местный бизнес, город |
| `рынок: вайб-клуб` | Участники и сам клуб                    |
| `рынок: любой`     | Продукт не привязан к городу            |

### Кто нужен — сколько угодно

| Метка            | Что значит                      | Кому смотреть                 |
| ---------------- | ------------------------------- | ----------------------------- |
| `нужен владелец` | Вести идею некому               | Тем, кто хочет повести проект |
| `нужны люди`     | Владелец есть, собирает команду | Тем, кто хочет поучаствовать  |

Флаги снимаем, когда нужда закрыта: владелец нашёлся, команда собралась.

## 🏁 Как идея заканчивается

| Что случилось                | Как закрываем на GitHub  | Что пишем в последнем комментарии                         |
| ---------------------------- | ------------------------ | --------------------------------------------------------- |
| Запустили, есть пользователи | **Close as completed**   | Что получилось, ссылка на продукт и репозиторий           |
| Закрыли                      | **Close as not planned** | Почему: пригодится следующему, кто придёт с похожей идеей |
| Такая идея уже есть          | **Close as duplicate**   | Ссылка на основную идею                                   |

«Not planned» — просто название кнопки на GitHub, переименовать её нельзя. У нас это «закрыта»: закрытую идею можно открыть снова, если что-то изменилось.

## 🗓 Спринты

Идеи, которые взяли в спринт, отмечаем milestone спринта, например «Спринт 1 · декабрь – январь». Так у каждого спринта есть список идей, и он сохраняется после спринта.

## 🚀 Когда по идее начинается работа

Работа идёт в отдельном репозитории `proj-<название>`, а issue идеи остаётся открытым до конца и собирает всю историю.

1. **Связать репозиторий и идею.** В описание issue добавляем ссылку на репозиторий проекта, ставим `стадия: разработка`. В README проекта пишем: `Идея: batumi-vibe-lab/ideas#12`.
2. **Ссылаться на идею из работы.** В описании PR или в сообщении коммита проекта пишем `Refs batumi-vibe-lab/ideas#12` — ссылка появится в ленте issue идеи, и по ней видно, что происходит.
   > ⚠️ Не пиши `Closes`, `Fixes` или `Resolves` с номером идеи: GitHub закроет идею при вливании первого же PR. Эти слова — только для задач самого проекта.
3. **Задачи проекта — подзадачами идеи** (по желанию). В issue идеи: **Create sub-issue → Add existing issue** и выбрать задачу из `proj-*`. На странице идеи появится прогресс: сколько задач закрыто.

## ⚙️ Как это устроено

- `.github/ISSUE_TEMPLATE/idea.yml` — форма идеи, ставит `стадия: идея`.
- `.github/workflows/idea-labels.yml` — ставит метки цели, рынка и `нужен владелец` по ответам формы.
- `.github/workflows/setup-labels.yml` — создаёт и обновляет все метки. Запуск: **Actions → Настроить метки → Run workflow**.

Меняешь варианты ответа в форме или названия меток — поменяй во всех трёх файлах.

> 🔒 Репозиторий приватный. Не выкладывай чужие идеи наружу без согласия авторов и не прикладывай к issues ключи, токены и личные данные.
